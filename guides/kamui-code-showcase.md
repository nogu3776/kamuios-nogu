# Kamui Code Showcase 利用ガイド

このドキュメントは、Kamui Code Showcase を初めて利用する方向けの操作手順と運用ポイントをまとめたものです。OSS 版をクローンした利用者が、このガイドに沿ってセットアップ・操作・アップデートを行えるよう構成しています。

## 1. 前提条件

- KamuiOS をローカルで起動できる状態であること（`./start_all.sh` が正常に動作する環境）。
- `.env` に `KAMUI_CODE_CONFIG_PATH`、必要に応じて `GEMINI_API_KEY`、`FAL_KEY` が設定済みであること。
- Python で FAL アップローダーを利用する場合は `fal-client` と `python-dotenv` をインストール済みであること。
- 生成先ディレクトリ（`static/showcase/`、`logs/showcase/` など）に書き込み権限があること。

## 2. 初期セットアップ

1. リポジトリをクローンした直後は `env.sample` を参考に `.env` を作成し、パス類を環境に合わせて書き換えます。
2. macOS / Linux / WSL 共通で以下を実行します。
   ```bash
   npm install
   ./start_all.sh
   ```
3. Windows (WSL2) 環境では、次の追加セットアップを推奨します。
   - `dos2unix start_all.sh .env` を実行し改行コードを LF に統一。
   - `SCAN_PATH` を WSL 形式の絶対パス（例: `/mnt/c/Users/<name>/kamuios-nogu/static`）で指定。
   - `pip install fal-client python-dotenv` を仮想環境内で実行し、`.env` に `PYTHON_PATH=/path/to/.venv/bin/python3` を追記。
   - ブラウザの自動起動は無効のため、`http://localhost:1313` を手動で開く。

## 3. 画面構成

Showcase 画面は以下の 3 ペインで構成されています。

- **左ペイン（MCP一覧）**: 利用可能な MCP が一覧表示されます。カテゴリでグループ化されており、検索バーで絞り込みが可能です。
- **中央ペイン（プロンプト入力 & 生成結果）**: 上部にプロンプト入力欄とファイル接頭辞の指定欄があり、選択中のプロンプトテンプレート名とメモが表示されます。`ジェネ`・`テンプレ`・`生成を開始` の 3 ボタンが並び、`ジェネ` はプロンプトジェネレーター、`テンプレ` はプロンプトテンプレート一覧、`生成を開始` はジョブ送信を実行します。プロンプトジェネレーターの「Gemini Instructions」を編集すると、Gemini への指示をカスタマイズできます。生成結果は同じ中央ペイン内のアウトプットビューにカード形式で表示され、プロンプト情報やメタデータの確認、右上ボタンからの拡大表示、動画カードの再生・一時停止が可能です。
- **右ペイン（生成履歴）**: 過去の実行履歴が時系列で表示され、選択すると中央ペインの生成結果ビューに反映されます。

## 4. 基本的な操作フロー

1. 左ペインから利用したい MCP を選択します。
2. 画像や動画などのインプットが必要なテンプレートでは、中央ペイン上部の「インプット」タブから必要なメディアを選択します。
3. プロンプト入力欄にテキストを記述します。テンプレートを適用したい場合は `テンプレ` ボタンから選択・新規作成・編集・削除が可能です。
4. プロンプトをブラッシュアップしたい場合は `ジェネ` ボタンでプロンプトジェネレーターを起動します。エンハンス（強化）または水平展開（バリエーション）を選び、生成結果から「採用」「コピー」「テンプレに追加」を選択できます。採用すると現在のプロンプト入力欄に反映されます。
5. 準備が整ったら `生成を開始` ボタンを押してジョブを送信します。
6. 生成が完了すると中央ペインの出力ビューにカードが並びます。`static/showcase/` にファイルが保存されます。

## 5. 生成結果の保存場所

| 種別 | 保存先 | 備考 |
|------|--------|------|
| 生成メディア | `static/showcase/` | 画像・動画など Showcase で作成されたファイル一式。Git 管理外のため定期的な外部バックアップを推奨。 |
| 生成ログ | `logs/showcase/*.log` | 日付ごとに分割保存。トラブル調査用。不要になったら手動で削除可能。 |
| プロンプト履歴・カスタムテンプレ | `logs/showcase/state/` | 生成メタデータと追加登録したプロンプトテンプレートを保持。テンプレ追加や生成実行のたびに更新。 |
| UI プリファレンス | `static/data/showcase/prompt-template-prefs.json` | 最近使用したテンプレートやタブ状態。必要に応じてコピーでバックアップ。 |

これらのファイル・ディレクトリは `.gitignore` に含まれているため、`git status` には表示されません。アップデートやクリーンアップの際に失いたくないデータがあれば、外部ドライブ等へ都度バックアップしておくことを推奨します。

## 6. トラブルシューティング

- **生成が始まらない / ロードが長い**: 初回は MCP の読み込みに時間がかかります。ターミナルで `logs/showcase/<日付>.log` を確認し、エラーがないかチェックしてください。
- **Python アップローダーで失敗する**: `pip list | grep fal-client` でインストール済みか確認し、仮想環境が有効になっているかを再確認します。
- **ブラウザが開かない (WSL)**: WSL2 では自動起動しないため、Windows 側ブラウザで `http://localhost:1313` を手動で開いてください。

## 7. バージョンアップ時の注意

1. `git status` でローカル変更を確認し、テンプレートファイルなど追跡対象を編集している場合はコミット・スタッシュする。
2. 個人データを保護するため、以下を外部にコピーしてバックアップ。
   - `static/showcase/`（生成したすべてのメディア）
   - `logs/showcase/state/`（生成履歴・カスタムプロンプトテンプレート）
   - `static/data/showcase/prompt-template-prefs.json`（UI プリファレンス）
3. `git pull` 後に `npm install` や `npm run build` が必要な場合は README の案内に従う。
4. 最新化後は Showcase を起動し、プロンプトテンプレートが読み込まれているか、生成履歴が表示されるかを簡単に確認する。
